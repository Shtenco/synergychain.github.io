Это эволюция одной системы: сначала богатая сеть страниц/идей, затем evidence/accounting discipline, потом Financial OS, non-destructive preservation и наконец normalized multi-page architecture.

Economic Constitution, source-of-funds, evidence levels, token naming conflicts, governance boundaries.

Financial OS Kernel

Four planes, xETH/SYUSD/USDCx separation, SettlementRouter, liabilities, consolidated NAV, QE/QT solvency constraints.

V17

Preserve + Unify

Literal preserved Growth OS + Financial OS Deep + Knowledge Hub + unified atlas. Главный урок: новая архитектура не должна уничтожать работающий слой.

Top Architecture

Domains, entity schema, shared design system, multi-page Financial OS, Explorer and explicit provenance.

RULE

No silent deletion

Любой historical concept получает mapping: preserved, superseded, deprecated, merged or contradicted — но не исчезает молча.

03 · MIGRATION STATES

Каждый legacy объект получает явный статус.

Так мы избегаем двух крайностей: «всё старое истина» и «всё старое удалить».

StateMeaningAction
PreservedИсторическая/рабочая версия остаётся как есть.Link from Archive and canonical successor.
SupersededЕсть новый canonical definition.Old page remains; redirect/context explains successor.
MergedНесколько старых сущностей объединены.Keep aliases and source references.
DeprecatedИдея больше не рекомендуется.Explain reason and last valid context.
ContradictedEvidence опровергает старый claim.Preserve claim + negative evidence + corrected model.
Research-onlyСлишком мало evidence для production.Move to Research, keep hypothesis.
04 · NAMING PROVENANCE

Имена меняются. Сущность должна оставаться прослеживаемой.

SYNG/SYNA/SYNC/SYNR/USDS/SYUSD/USDCx — пример того, почему нужен alias registry. UI не должен автоматически считать похожие тикеры одной и той же ролью.

Canonical ID

Независимый от маркетингового названия machine ID: например `fin.syusd`.

Display name

Текущее human-readable имя.

Legacy aliases

Старые тикеры, product names, page titles and contract generations.

05 · NEGATIVE EVIDENCE MEMORY

Ошибки — тоже часть интеллектуального капитала.

В архиве особенно важны failure results, потому что именно они объясняют, почему в V18 появились Liability Registry, affordable gradient, prefunded receivables, QE neutralization и canonical profit guard.

Bridge support exceeded apparent gains

Показал, что agent profit/TVL growth может финансироваться depletion/new backing.

QT required real budget

Показал asymmetry expansion/contraction.

Temporary LP captured QE

Привёл к pro-rata QE neutralization invariant.

06 · MEMORY PRINCIPLE

Система, которая забывает ошибки,
обречена снова назвать их инновацией.

Поэтому Archive — не склад старых файлов, а reasoning provenance: какой claim существовал, какое evidence пришло позже и почему canonical rule изменился.
