02 · INPUT STATE

NEXUS получает структурированное состояние.

Вместо огромного prompt с «всем проектом» ему нужны versioned machine-readable views.

Financial state

Assets, liabilities, reserves, receivables, policy budget, realized/unrealized P&L, risk limits.

Product state

Users, revenue, cost, delivery obligations, incidents, conversion and capacity.

Governance state

Active mandates, proposals, conflicts, timelocks, delegated roles and expiring permissions.

Infrastructure state

Chain health, bridge coverage, services, latency, errors, deploy/version status.

Research state

Evidence level, unresolved hypotheses, failed tests and promotion gates.

Household / social aggregate

Only privacy-safe/authorized aggregate state: liquidity stress, debt load, program demand, not uncontrolled personal surveillance.

03 · OUTPUT CONTRACT

Proposal должен быть исполняемым и проверяемым.

Хороший NEXUS output — не «совет». Это structured proposal with objective, evidence, action scope, expected post-state, risk, uncertainty and stop condition.

04 · AUTHORITY FIREWALL

Самая важная часть NEXUS — чего он не может.

No unrestricted signing key

Model cannot hold universal Treasury/bridge/admin key.

No constitutional mutation

AI cannot lower backing floors or rewrite rights by confidence score.

No hidden action

External spend, governance mutation and claim creation require explicit audit event.

Scoped capability

Execution token specifies method, amount, entity, expiry and allowed post-state.

Human/institution challenge

Proposal and execution rationale remain reviewable.

Fail closed

If required state/evidence missing, NEXUS must not invent permission.

05 · DECISION MODES

Разные задачи требуют разных агентных структур.

OLGA/Growth OS already explored single, chain, consensus, debate and department modes. NEXUS can reuse these patterns at system level, but with structured evidence and bounded outputs.

Single analyst

Low-risk summarization / anomaly triage.

Chain

Sequential specialist handoff.

Consensus

Independent models compare conclusions.

Debate / red team

Proposal vs critic vs arbiter for high-risk decisions.

06 · INTELLIGENCE PARADOX

Чем умнее система,
тем важнее ограничить её права.

Высокая predictive ability увеличивает потенциальную пользу — и цену ошибки/захвата. Поэтому capability and authority должны расти независимо.

07 · EVIDENCE

NEXUS сам должен быть наблюдаемым.

Decision logs, model/version, input state hashes, proposal diffs, approval path, execution result, post-state error, incidents and rollback effectiveness.
