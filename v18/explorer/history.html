EXPLORER · ALIASES / HISTORY / SUPERSESSION

Название меняется.
Сущность не должна исчезать.

Эта поверхность хранит legacy aliases, явно запрещённые «ложные синонимы», version events и migration history. Это защищает СИНЕРГИЮ от самой опасной ошибки большого проекта: когда новое имя незаметно меняет экономический смысл старого объекта.

↺
01 · FOCUS

История конкретной сущности.

Откройте через `?entity=` или найдите по ID/имени. Паспорт каждой сущности ведёт сюда.

Показывается общая история V14 → V18.
02 · VERSION EVENTS

Что изменилось и почему.

History event — не git commit. Это семантическое изменение роли, taxonomy, accounting или migration state.

03 · ALIAS REGISTRY

Старые имена остаются прослеживаемыми.

`legacy-ambiguous` означает: имя встречалось исторически, но нельзя автоматически мигрировать balances/claims без формального governance mapping.

04 · EXPLICIT NON-ALIASES

Похожие названия иногда означают разные claims.

Эти пары запрещено автоматически merge-ить в поиске, миграции или accounting.

05 · MEMORY

Если новое имя стирает старый смысл,
система теряет audit trail.

V18 поэтому хранит ID независимо от display name и отделяет alias от equivalence.
